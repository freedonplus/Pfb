# 分轮提问脚本（前端）

每轮最多 4 个问题，使用 AskUserQuestion 工具。选项中推荐项放第一位并标注「（推荐）」。
回答会裁剪后续轮次：标注了「剪枝」的轮次在条件不满足时整轮跳过。

---

## 第 1 轮 · 平台与终端（必问）

本轮目的：确定交付形态，决定构建工具链、运行时约束与后续所有问题的方向。

1. **目标平台**（可多选思路，先定主平台）
   - 网站 / Web H5（推荐）：浏览器访问，含 PC 与移动端
   - 移动 App：需要安装包
   - 微信小程序
   - 桌面端：Windows / macOS 安装包

2. **App 技术栈**（仅选了「移动 App」时问）
   - uni-app x（uvue/UTS，推荐：一套代码多端，编译为原生）
   - Flutter（极致性能，Dart 生态）
   - React Native
   - 安卓/ iOS 原生（Kotlin/Swift）

3. **Web 目标环境**（仅网站/H5 时问）
   - PC 为主（后台管理类，推荐）
   - 移动 H5 为主（微信内打开、浏览器）
   - PC + 移动自适应

4. **是否需要多平台一套代码**
   - 不需要（推荐）：聚焦一个平台，技术栈最纯粹
   - 需要：优先考虑 uni-app x / Taro 等跨端方案

---

## 第 2 轮 · 语言与框架（必问，选项随平台变化）

本轮目的：锁定语言、框架与构建工具基线。

1. **开发语言**（桌面端/小程序/App 已限定语言时跳过）
   - TypeScript（推荐）：大型项目类型安全、可维护性强
   - JavaScript：小项目 / 快速原型

2. **框架**（Web / uni-app 场景）
   - Vue 3 + Vite（推荐，国内生态与团队上手成本最优）
   - React 18+ + Vite（生态最丰富，复杂交互/大厂背书）
   - Svelte / Solid（性能极致，生态较小，Other）
   - uni-app x（选 App 平台时的默认）

3. **构建工具**
   - Vite（推荐）：dev 秒级、ESM 原生
   - webpack 5：存量项目 / 需要 Module Federation
   - Rspack：webpack 兼容 + Rust 提速（大型 webpack 存量项目）

4. **组件库需求**
   - 需要成熟组件库（推荐）：后台类必选，见第 3 轮
   - 自研设计系统：有专门设计师与组件开发人力
   - 纯定制样式：C 端活动页/官网风格强烈

---

## 第 3 轮 · 组件库与样式方案（剪枝：后台纯用成熟库时跳过第 2 问；纯定制样式只问样式工程化）
> 第 2 问「视觉组件复用策略」为条件题，仅 C 端 / 品牌官网 / 开发者产品时提出，不计入每轮 4 问上限。

1. **UI 组件库**（按框架给选项；完整目录、默认推荐矩阵与活跃度三门槛见 `component-libraries.md`——star ≥ 3k 或大厂背书、近 6 个月有发版、issue 响应正常）
   - Vue 3：Element Plus（推荐，后台标配）/ Naive UI / Ant Design Vue / Vant（移动 H5）
   - React：Ant Design（推荐）/ MUI / Semi Design / shadcn-ui + Tailwind
   - uni-app x：自研样式（推荐，组件库支持有限）/ uni-ui x
   - 小程序：Vant Weapp（推荐）/ TDesign 小程序版 / Lin UI

2. **视觉组件复用策略**（C 端 / 品牌官网 / 开发者产品时问；后台纯用成熟库可跳过）
   - 成熟库为主 + 少量 uiverse 式自研视觉组件（推荐）：重交互用库，按钮/开关/加载动画等轻交互高视觉组件抄改 uiverse.io / shadcn 生态，过 `ui-patterns.md` §一准入门槛收编进设计系统
   - 完全自研设计系统：有设计师与组件团队
   - 全部用成熟库默认样式：最快但无差异化

   **设计风格**（与上问同轮或紧随其后，按项目类型从 `ui-patterns.md` §二 StyleKit 映射表给 3~4 个候选，如后台 → 企业简洁风/Notion 风/暗黑模式，SaaS 官网 → 现代渐变风/柔和界面风/Apple 风；用户选定后写入方案书「选择 + 理由 + 否决项」）

3. **样式工程化**
   - CSS 预处理器 + scoped/Modules（推荐）：Sass/Less + 组件级隔离
   - Tailwind CSS：原子化，适合定制风格与快速迭代
   - CSS-in-JS：React 生态可选（styled-components / emotion）
   - 现代 CSS 原生方案：@layer 级联治理 + 设计 token + 容器查询（项目无旧浏览器包袱时推荐与上项组合，见 `ui-patterns.md` §五）

4. **图标与字体**
   - SVG 图标库（推荐：iconify / 自托管 SVG sprite）
   - iconfont 字体图标
   - 需要自定义字体（品牌字体，注意字体子集化）

5. **主题与暗黑模式**
   - 不需要（推荐，按默认浅色）
   - 需要暗黑模式 / 主题切换（CSS 变量 token 方案，`light-dark()` 增强可选）

---

## 第 4 轮 · 规模与流量模型（必问，决定是否加载高阶清单）

本轮目的：判断是「常规项目走主清单」还是「高流量 C 端叠加高阶清单」。

1. **项目类型**
   - 后台管理 / 内部系统（推荐）：员工使用，无公网流量压力
   - 公网 C 端常规：官网、普通电商，日 UV 万级以内
   - 公网 C 端高流量：百万级 UV、活动大促页 → 启用 advanced-checklist

2. **首屏性能要求**
   - 常规（推荐）：LCP < 2.5s 即可
   - 严格：秒开率考核、SEO 依赖首屏 → 考虑 SSR/SSG
   - 无要求：内部工具

3. **是否微前端 / 多应用**
   - 单体应用（推荐）
   - 微前端（qiankun / Module Federation）：多团队、多技术栈共存 → 启用 advanced 微前端小节

4. **多端状态与数据规模**
   - 常规 CRUD + 列表分页（推荐）
   - 大列表 / 大数据表（万级行）→ 虚拟滚动必做
   - 实时数据：WebSocket / SSE 推送

---

## 第 5 轮 · 渲染方式与数据层（剪枝：后台内部系统可简问）

1. **渲染方式**
   - CSR 纯客户端渲染（推荐：后台与 App 内嵌页）
   - SSR（Nuxt / Next）：SEO + 首屏性能双需求
   - SSG 静态生成：官网 / 文档 / 营销页

2. **状态管理**
   - 轻量方案（推荐）：Pinia（Vue）/ Zustand（React）/ Redux Toolkit（大型 React）
   - 不需要全局状态：页面级状态即可的小项目

3. **请求层封装**
   - 统一封装 fetch/axios 拦截器（推荐）：错误码、401 跳转、token 无感刷新
   - 引入数据请求库：SWR / TanStack Query（React）/ vue-request（Vue）

4. **国际化**
   - 不需要（推荐）
   - 需要 i18n：语言包懒加载、文案抽离不硬编码

---

## 第 6 轮 · 工程化与发布（必问）

1. **质量门禁**
   - ESLint + Prettier + 类型检查（推荐，全部启用）
   - 仅 ESLint
   - 暂不需要（不推荐，需说明理由）

2. **测试范围**
   - 关键业务单元测试（推荐）：Vitest / Jest
   - 组件测试 + E2E（Playwright）
   - 不做自动化测试（不推荐）

3. **CI/CD 与发布策略**
   - 流水线构建 + 静态资源托管（推荐）
   - 灰度发布：先小流量再全量
   - 手工发布（仅小项目）

4. **监控与埋点**
   - 需要：前端监控 SDK（错误捕获、性能指标、行为埋点）
   - 暂不需要（推荐内部工具从简）
